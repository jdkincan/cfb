Technical notes · cfbmeta 1.0

CFB Meta Forecast

A weekly college football handicapping system that distills the public rating systems into one projected margin per game, grades it against the market, and reports how much of the disagreement is worth betting.

Read this first

No live 2026 output exists yet. Every number in this document is either a configuration value, a formula, or a worked example built from synthetic fixtures. The system has never successfully reached collegefootballdata.com, because the environment it was built in blocks outbound traffic to every sports-data host at the network layer.

That is a property of the build environment, not of the code or the API key. python -m cfbmeta doctor from anywhere with open egress resolves it in about ten seconds, and is the first thing to run.

What the system is for

The premise is that building another rating from scratch is not where the edge is. Several good public ratings already exist, they disagree with each other in informative ways, and none of them adjusts for the specific circumstances of a given Saturday. The work is in the distillation, the adjustments, and — most of all — in being honest about how much of the resulting disagreement with the betting market is real.

Output is one email per week containing every game on the slate: the model's number, the market's number, the gap between them, a probability, and a stake in units. Underneath each game sits a full audit trail, so any point of any projection can be traced to the thing that produced it.

Data sources

Everything comes from CFBD on a free API key, with one fallback. Five rating sources feed the blend; the remaining endpoints feed the adjustment layer.

SP+, FPI and SRS are already published as net points per game against an average opponent, so they need no conversion. Elo and the talent composite are not, so they are z-scored across FBS and stretched to match the standard deviation of that season's SP+ ratings. The conversion therefore recalibrates itself every year instead of depending on a constant that slowly goes stale.

FPI has a second path

FPI reaches the model through CFBD's /ratings/fpi, which mirrors ESPN on its own ingest schedule. Those diverge early in a season. If CFBD's FPI comes back unusable the run falls back to ESPN's public power-index endpoint directly, filling only teams already in the book so an unmatched name never invents a team no game refers to. The audit line records which provider supplied it.

A source with no opinion is not a weak opinion

The dangerous preseason failure is not a missing source — that degrades cleanly. It is a source that returns a row for every team with all the values identical, which is what an August SRS looks like. Blended, that predicts a tie in every game and drags the whole slate toward pick'em while the run looks perfectly healthy.

So any source with fewer than 10 rated teams or under 0.5 points of spread between them is dropped outright and the weights renormalize over what remains. Every source's status is recorded and printed in doctor, in the run log, and in the footer of the email itself: 

OK    SP+ 2026: 136 teams (spread 14.2)
OK    FPI 2026: 134 teams (spread 14.0) via ESPN
OK    Talent 2026: 136 teams (spread 10.5)
WARN  SRS 2026: unusable — all 136 teams within 0.00 pts — no games played yet
WARN  Elo 2026: unusable — all 136 teams within 0.00 pts — no games played yet

If no source is usable the run fails loudly with that audit attached, rather than emitting a slate of zeros.

The pipeline

  1. Each source proposes a neutral-field margin

    Home rating minus away rating, in points. A source missing either team drops out and the weights renormalize over the rest.

  2. Blend by weight

    A weighted mean over whichever sources actually showed up, not over the full configured set.

  3. Add home field once

    On top of the blend, not per source — every source is quoted as a neutral-field rating, so adding it per component would multiply it.

  4. Apply situational adjustments

    Coaching, rest, travel. Each capped individually, then capped again in aggregate at ±4 points.

  5. Compare against the market

    The difference is the raw edge. What happens to it next is the most consequential decision in the system.

Why market weight is zero

The closing line is the benchmark the system is trying to beat. Folding it into the forecast would launder away the very disagreement being measured — the model would agree with the market by construction and report a small edge that means nothing. It stays an input to the comparison, never to the projection. Raise it only if a backtest shows the blend is genuinely worse than the line.

Home field, per venue

Every rating already bakes an average home field into itself, but home field is not uniform. The estimator uses each team as its own control:

raw_hfa(team) = (mean margin at home − mean margin away) / 2

Team quality cancels out of the difference, leaving mostly venue effect plus noise. Because it is noisy, it is shrunk hard toward the league mean with a 60-game pseudo-count:

hfa = (n · raw_hfa + 60 · league_mean) / (n + 60) — clamped to [0, 5]

The league mean itself is re-centred on what five seasons of results actually show rather than left as a constant. Altitude is handled separately, as a differential against where the visitor normally plays — Wyoming hosting Florida is a real edge, Wyoming hosting Air Force is not.

Coaching, measured against talent

"Good coach" is easy to assert and hard to quantify. The measurable version: fit how much SP+ rating a team's recruiting talent buys on average, then credit the coach with the residual.

expected_sp = slope · talent_z + intercept residual = actual_sp − expected_sp score = Σ(residual · 0.75^age) / Σ(0.75^age) · den/(den + 3)

Recent seasons count more, career length shrinks the result toward zero, and a first-year hire takes a 1.2-point penalty for scheme turnover and roster fit. The whole thing is capped at ±1.5 points. It is a tiebreaker on close games, never a driver.

Uncertainty

Margins are modelled with σ ≈ 16 points. But college football margins are not smoothly normal — they pile up on 3 and 7, and to a lesser degree 10, 14, 17 and 21. A plain normal misprices any bet sitting on a key number, so the distribution is discretized over integers and those are reweighted:

P(margin = m) ∝ φ((m − μ)/σ) · key(|m|), m ≠ 0

Edge shrink

This is the most important idea in the system, and the one most handicapping tools get wrong.

Taking a raw disagreement at face value assumes our number is correct and the closing line is wrong by that full amount. It is not. The closing line is the sharpest public estimate that exists, and when a model built from public ratings disagrees with it by seven points, most of that gap is our error, not theirs. So only a fraction of the disagreement is treated as signal:

edge = projected_margin − market_margin settled = market_margin + edge · 0.35 cover, stake computed from `settled`, never from `projected`

The raw edge is still reported — that is the honest description of the disagreement — but the money is sized off the shrunk one. backtest --fit estimates the right fraction by regressing actual margins on the market line and on our disagreement with it; the coefficient on the disagreement is the shrink. Values near 0.2–0.4 are typical. Anything approaching 1.0 should be read as a bug or as lookahead contamination, not as an edge.

What this changed

The first working build had no shrink. Every play came out at the 3-unit cap quoting 65% cover, because a 6.6-point disagreement looks enormous when you assume you are right. With the shrink, the same slate produced stakes ranging from 0.37u to 2.36u and cover probabilities between 53% and 55% — which is what a real edge actually looks like.

Staking

Quarter-Kelly against a 100-unit bankroll, capped at 3 units, priced at −110.

b = 0.909 — profit per unit at −110 EV = p · b − (1 − p) kelly = (b · p − q) / b — q renormalized over non-push outcomes units = kelly · 0.25 · 100 — capped at 3.0

A push returns the stake, so it is excluded from both sides rather than counted as a loss. Nothing under 1.5 points of raw edge is called a play, and nothing with non-positive EV is either.

Backtesting, and one caveat that matters

backtest measures MAE, RMSE, σ, bias, ATS record against the closing line, and calibration by probability bucket. With --fit it re-estimates the blend weights, σ, and the edge shrink from real results.

Lookahead

CFBD serves end-of-season SP+, FPI and SRS for a given year. Using those to "predict" that same year's games is lookahead — the ratings already know how the games turned out, which inflates accuracy and makes σ look far too small.

So the default basis rates every game using the previous season's final ratings, which genuinely existed before kickoff. It understates in-season accuracy, but it never flatters the model. --basis same exists for ranking the sources against each other, since the contamination affects them similarly — its error figures are labelled untrustworthy in the output, and --write refuses to save anything derived from them.

Scheduling

GitHub Actions cron speaks only UTC, and 7am Eastern is 11:00 UTC in September but 12:00 UTC after the November clock change. The workflow fires at both hours every Thursday and the run exits immediately unless the local hour actually matches. Exactly one of the two does the work, all season, with no schedule edit at the boundary — there is a test that walks 20 consecutive Thursdays across the change and asserts exactly one fire per week.

Out of season no upcoming week resolves and the run exits quietly. Email delivery is currently held behind a SEND_EMAIL repository variable; until it is set to true the workflow still builds the full slate and uploads it as an artifact, but sends nothing.

Credentials

This repository is public. A key committed to it, or passed as a workflow input where it lands in publicly readable logs, is scraped by bots within minutes and will often be revoked automatically by GitHub's secret scanning. Keys belong in repository secrets, which are masked in logs, or in the gitignored .env locally.

What is verified, and what is not

The 239 tests cover the blend arithmetic, HFA shrinkage, coaching residuals, the margin distribution and key numbers, EV and Kelly, the edge shrink (including recovering a known signal fraction from synthetic data), report rendering, the DST schedule gate, week 0 handling, preseason source pruning, and four plausible shapes of the ESPN payload. None of them touch the network.

What that leaves genuinely unverified:

  • CFBD response shapes. Field names and endpoint paths are handled tolerantly — both casings, several candidate paths — but never confirmed against the live API. doctor is what confirms them.
  • ESPN's payload structure. The endpoint is undocumented. The parser searches for a team name and an FPI-labelled value wherever they sit rather than assuming a path, and marks FPI unusable if it finds nothing.
  • Whether 2026 data exists yet for any given source. That is exactly what the source audit reports.
  • Every default. Weights, σ, and the edge shrink are priors. Until backtest --fit has run against real seasons, they are reasonable guesses, not measurements.
First three things to run

doctor to confirm the API and see which sources have 2026 data. Then backtest --years 5 --fit --write to replace the priors with measurements — this also answers whether the blend beats the closing line at all, which is the question worth settling before reading a single weekly email. Then preview --week 0.
